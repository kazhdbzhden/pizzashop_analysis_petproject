# Pizza Shop — System Analysis Pet Project

## О проекте

Pet-проект по системному анализу веб-системы для онлайн-заказа пиццы.

Проект демонстрирует процесс проработки информационной системы со стороны
системного аналитика: от анализа предметной области и определения
функциональности до формирования требований, моделирования процессов,
проектирования API и создания прототипа интерфейса.

## Цель

Провести системный анализ веб-системы пиццерии и сформировать требования
и проектные решения, необходимые для её последующей разработки.

## Практическая направленность

Проект моделирует задачу подготовки аналитической и технической основы
для разработки веб-системы онлайн-заказа пиццы.

Полученные материалы позволяют определить:
- функциональность системы;
- роли и сценарии взаимодействия пользователей;
- требования к системе;
- основные бизнес-процессы;
- взаимодействие компонентов системы;
- структуру API;
- основные сущности и связи между ними;
- требования к пользовательскому интерфейсу.

## Результат

В результате проекта разработан комплект аналитических артефактов,
описывающих концепцию и требования к системе:

- конкурентный анализ;
- описание MVP;
- системные роли;
- функциональные требования;
- модели бизнес-процессов;
- UML-диаграммы;
- модель данных;
- спецификация REST API;
- прототип пользовательского интерфейса.

## Предметная область

Веб-система пиццерии для оформления и управления онлайн-заказами.

Основные процессы системы:
- просмотр каталога;
- выбор и настройка блюд;
- работа с корзиной;
- оформление заказа;
- отслеживание статуса заказа;
- просмотр истории заказов;
- управление каталогом со стороны администратора.

## Основные пользователи

### Клиент

- регистрация и авторизация;
- просмотр каталога;
- выбор и настройка блюд;
- добавление товаров в корзину;
- оформление заказа;
- просмотр статуса заказа;
- просмотр истории заказов.

### Администратор

- управление каталогом блюд;
- управление информацией о товарах;
- обработка заказов.

## Аналитические артефакты

### 1. Конкурентный анализ

Анализ решений конкурентов и выявление функциональных и UX-особенностей,
которые могут быть использованы при формировании требований к системе.

### 2. MVP

Определение минимального набора функциональности, необходимого для
запуска системы.

### 3. Требования

Описание бизнес-, функциональных и нефункциональных требований к системе.

### 4. BPMN

Моделирование основных бизнес-процессов системы с использованием BPMN.

### 5. UML

Диаграммы взаимодействия и поведения системы, включая sequence diagram.

### 6. Data Model

Моделирование основных сущностей системы и связей между ними.

### 7. API

Проектирование и документирование REST API для взаимодействия клиента
с серверной частью системы.

### 8. Prototype

Прототип пользовательского интерфейса и основных пользовательских
сценариев в Figma.

## Основные пользовательские сценарии

### Просмотр каталога

Клиент открывает каталог, выбирает категорию и просматривает доступные
блюда.

### Формирование заказа

Клиент выбирает блюда, добавляет их в корзину, указывает необходимые
данные и подтверждает заказ.

### Отслеживание заказа

После оформления клиент может просматривать текущий статус заказа.

### Управление каталогом

Администратор добавляет, изменяет и удаляет информацию о блюдах.
